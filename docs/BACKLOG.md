# Отложено на потом

## Лиды и аналитика (вместо Shopify)
Решение: лиды храним внутри Platofy, письма отправляем через Resend, аналитика — PostHog. Shopify не подходит, потому что он для интернет-магазинов, а у нас подписка через Stripe.

### Лиды
- **Модель.** Новая таблица `leads` (старый waitlist удалён):
  - `kind`: pilot / contact / signup;
  - `status`: new / contacted / pilot / customer / lost;
  - имя, заведение, телефон, число точек, размер команды, сообщение;
  - UTM-метки, referrer, заметки, `organization_id`.
  - Одна запись на email: повторная заявка обновляет старую.
- **Эндпоинт** `POST /marketing/leads` — публичный, с лимитом по IP и полем-ловушкой от ботов.
- **Регистрация владельца** автоматически создаёт или обновляет лид: `kind=signup`, `status=customer`, с UTM.
- **Письма через Resend:**
  - лиду — «спасибо, свяжемся»;
  - на `PLATFORM_ADMIN_EMAILS` — «новая заявка на пилот».
- **Страница `/pilot`** с формой заявки (EN/PL/RU), кнопка «Join the pilot» на лендинге. UTM и referrer сохраняются при первом визите.
- **«Платформа → Лиды»:**
  - фильтры, поиск, статус, заметки, mailto, экспорт CSV;
  - запись действий в `PlatformAuditLog`.

### PostHog
- `posthog-js` грузится только при заданном `VITE_POSTHOG_KEY` и после согласия с cookie. Запись сессий с маскировкой полей ввода.
- `identify(user)` и `group(organization)` после входа, `reset()` при выходе.
- **События воронки:**
  - `pilot_form_submitted`, `signup_completed`, `team_invited`;
  - `schedule_generated`, `schedule_published`, `kiosk_set_up`, `checkout_started`.
- **Чек-лист:** аккаунт PostHog (EU), переменная `VITE_POSTHOG_KEY` в Railway, воронка «сайт → регистрация → первый опубликованный график».

## Приложения в Google Play и App Store
- Упаковать приложение в Capacitor.
- Нативные пуши через FCM и APNs.
- Вход по токену и удаление аккаунта внутри приложения.
- Скрыть оплату в iOS-версии.
- Сборки через GitHub Actions.
- Нужны от владельца: домен, аккаунты разработчика ($25 Google, $99/год Apple), D-U-N-S для компании.
